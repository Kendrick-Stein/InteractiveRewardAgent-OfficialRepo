# Interactive Reward Agent

Official clean repository for **Interactive Reward Agent (IRA)** and **GUI-RewardBench**.

IRA is a GUI task-completion evaluator built around a propose-then-verify workflow. Instead of judging a final screenshot directly, it proposes task-specific completion conditions and verifies them through system tools, application tools, file inspection, accessibility inspection, and GUI interaction when needed.

## Highlights

- **86.9% accuracy** on GUI-RewardBench with the GPT-5.5 IRA evaluator.
- **321 stable GUI task trajectories** across **10 Ubuntu desktop categories**.
- Evidence-grounded verification over screenshots, generated files, application preferences, system settings, and live GUI state.
- Config-driven **parallel sample replay** for replaying GUI-RewardBench trajectories and comparing IRA against `env.evaluate()`.
- Static project pages live under [`docs/`](docs/index.html) and can be published directly with GitHub Pages.

## Repository Layout

```text
RewardAgent/             Core IRA implementation.
ira_replay/              Config-driven parallel sample replay runner.
configs/                 YAML configuration for local replay testing.
visualization/           Lightweight report rendering helper used by RewardAgent.
rewardbench_examples/    321 GUI-RewardBench task JSON files.
docs/                    Static GitHub Pages site and figure assets.
benchmark_manifest.json  Benchmark category summary.
```

This clean repository intentionally excludes raw replay caches, large outputs, debug reports, local credentials, and experiment result directories. If a local directory has been removed from this clean repo, it should not be regenerated by the publishing workflow.

## Installation

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and fill in your credentials. The IRA evaluator works
with any OpenAI-compatible endpoint:

```bash
IRA_API_KEY=your-api-key
IRA_BASE_URL=https://your-openai-compatible-endpoint/v1
```

IRA expects the host project to provide a compatible `desktop_env` environment object. The recommended Docker-based environment setup is [Computer-use-agents/GUI-Docker-Env](https://github.com/Computer-use-agents/GUI-Docker-Env), which provides the OSWorld-style `desktop_env` server and Docker simulator used by this line of work.

## Parallel Sample Replay

The official repo includes a clean replay entrypoint migrated from the research repo:

```bash
python -m ira_replay.parallel_sample_replay \
  --config configs/parallel_sample_replay.yaml \
  --dry-run
```

After `desktop_env` is installed and the Docker server is running, edit `configs/parallel_sample_replay.yaml`:

```yaml
desktop_env:
  provider_name: docker_server
  base_url: http://127.0.0.1:50003
  token: reward

tasks:
  categories: [chrome]
  max_tasks_per_category: 1

replay:
  output_dir: runs/parallel_sample_replay
  max_workers: 1

reward_agent:
  enabled: false
```

Run the replay:

```bash
python -m ira_replay.parallel_sample_replay --config configs/parallel_sample_replay.yaml
```

Set `reward_agent.enabled: true` when you want IRA to score the replayed final state; the LLM endpoint is taken from `IRA_API_KEY` / `IRA_BASE_URL` in your `.env` (or from `reward_agent.client` in the YAML). The runner writes `summary.json`, `summary.csv`, per-task screenshots, replay logs, and reward comparisons under the configured `runs/` directory. Runtime outputs are ignored by git.

## GUI-RewardBench

The benchmark JSON files are organized by category:

```text
chrome, gimp, libreoffice_calc, libreoffice_impress, libreoffice_writer, multi_apps, os, thunderbird, vlc, vs_code
```

Each task JSON contains the instruction, environment configuration, related apps, recorded trajectory metadata, and evaluator specification. The full manifest is in [`benchmark_manifest.json`](benchmark_manifest.json).
